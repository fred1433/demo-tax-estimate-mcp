Parity with FileTax engine: to verify after access. Matching IRS tables is not the same promise as matching FileTax.com's engine to the dollar; that needs its ten reference profiles or its API.

Refused, never estimated (one test each):

  • eic_may_apply: With $40,020 of wages and 1 qualifying child, the Earned Income Credit may apply (it phases out completely at $50,434 for 2025). This stand-in engine does not compute it, so it gives no estimate rather than a wrong one.
  • situation_tips: Tips (Schedule 1-A, no tax on tips): not handled by this stand-in engine.
  • three_or_more_children: Three or more qualifying children use Schedule 8812 Part II-B, which this stand-in engine does not compute.
  • unsupported_filing_status: Married filing separately is not covered by this stand-in engine. Covered: single, married filing jointly, head of household.
  • age_65_or_older: Filers 65 or older get an additional standard deduction and may qualify for the senior deduction on Schedule 1-A. This stand-in engine does not compute them yet.
  • wages_above_limit: Wages above $200,000 bring in Additional Medicare Tax and credit phase-outs this stand-in engine does not handle.
  • head_of_household_not_confirmed: Head of household needs a confirmation that you are unmarried (or considered unmarried), paid more than half the cost of keeping up a home, and a qualifying person lived with you. This tool does not infer it from having a child.
  • situation_charitable_donations: Charitable cash donations (2026 deduction for non-itemizers): not handled by this stand-in engine.
  • eic_may_apply: With $18,000 of wages and 0 qualifying children, the Earned Income Credit may apply (it phases out completely at $19,540 for 2026). This stand-in engine does not compute it, so it gives no estimate rather than a wrong one.
  • child_rules_not_confirmed: The child tax credit needs a confirmation that each child is under 17 at year end, lived with you more than half the year, is your dependent, and has an SSN valid for employment, and that you (or one spouse on a joint return) have a valid SSN.

Line names follow the 2025 Form 1040. Every input is a full-year expected amount. Not computed, so refused: the Earned Income Credit, three or more children, other dependents, 65 or older, blindness, being someone's dependent, Schedule 1-A items (tips, overtime, car loan interest, senior deduction), the 2026 charitable deduction for non-itemizers, self-employment, investment income, itemizing, education, child care, retirement contributions, Marketplace insurance, foreign income, filing separately and wages over $200,000.

Logs and the Meta event

The Worker writes one kind of log line: a closed list of fields (event, surface, outcome, duration, a random correlation id, a code). Library output is replaced by a fixed marker. Invocation logs and traces are off. Workers Logs still attach the request URL to each line, so requests whose URL carries a query string (the OAuth authorization request) write no line at all. The page Worker, which receives the OAuth callback, has logging off.

Check on the live Worker, Nov 2, 2026: 16 steps (estimate, refusal, validation error, sign-in refused, sign-up, Save, repeated Save, tampered reference, invalid token, token refresh, on both endpoints) with recognisable values, then 20 values searched in 40 lines read back from Cloudflare Workers Logs (telemetry query API): 0 found. Fields seen: cid, code, evt, ms, outcome, surface.

Same check on a local run (with the expired-reference case): 0 found in 43 lines.

Meta Conversions API: preview only, never sent. After a confirmed sign-up (CompleteRegistration) and a confirmed first Save (Lead), the server stores the event it would send, deduplicated by event_id. It holds a hashed email, a hashed account id, the surface and the action source; no amount, no refund or balance category, no tax year, no IP address or user agent, since on ChatGPT and Claude the request comes from the host's servers, not from the taxpayer. No compliance claim is made.

OAuth and MCP, as built

  • Authorization server metadata: /.well-known/oauth-authorization-server. Client ID Metadata Documents, PKCE S256 only, RFC 9207 iss on every authorization response, resource indicators bound to one audience per token; Dynamic Client Registration kept for compatibility. Library: @cloudflare/workers-oauth-provider 1.2.4 with the global_fetch_strictly_public flag.
  • Claude: /mcp/claude. Discovery and the estimate work without a token; an unauthenticated save_estimate gets HTTP 401 with WWW-Authenticate before the MCP layer runs. Card ui.domain computed from the server URL as Claude documents.
  • ChatGPT: /mcp/chatgpt. securitySchemes per tool (noauth for the estimate, oauth2 for Save); an unauthenticated Save returns a tool error carrying _meta["mcp/www_authenticate"].
  • Both endpoints serve 2025-era clients (initialize handshake) and 2026-07-28 clients (stateless), through @modelcontextprotocol/server 2.4.0. One MCP Apps card (ui://tax-estimate/card.html, text/html;profile=mcp-app) with the MCP Apps SDK; Save goes through the host bridge and no token reaches the card.
  • Save: the estimate tool persists nothing (readOnlyHint: true); its reference is signed and expires after 24 hours. Save verifies it, recomputes with the same engine version and refuses if the result would differ. One record per account and estimate: a repeated Save returns the same record. The account comes from the validated token only.

What's left for a real submission

  • FileTax.com's engine behind the same tool contract, and its ten reference profiles to show parity to the dollar.
  • FileTax.com's account system as the sign-up and sign-in step, on a FileTax.com domain: Anthropic's review expects the server domain to match the service (Claude review criteria).
  • A sign-in path for an existing account with a password: OpenAI asks for a login and password for a fully featured demo account and rejects plugins whose review needs a new sign-up (plugin guidelines). The demo here only creates accounts.
  • OpenAI: verified developer identity, plugin ZIP with metadata, domain verification of the MCP host, five positive and three negative test cases, a video walkthrough, support, privacy and terms URLs (submission guide).
  • Anthropic: test credentials for a populated account, public documentation, privacy policy and support contact, and carousel screenshots for an MCP App (submission guide).
  • Why this demo is not submitted: it would list an app for FileTax.com's users under someone else's name, and OpenAI does not accept demo plugins (plugin guidelines).
